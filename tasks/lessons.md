# Lessons

- When assessing a product idea for a hackathon, distinguish technical feasibility and track fit from delivery planning. If the user prioritizes a finished product and says to ignore time or staffing, assess the complete architecture and its real dependencies; do not substitute an MVP or time-boxed scope.
- When adapting a named reference protocol, preserve its credit model, lender protection, and visibility unless the user asks for changes. Distinguish ordinary XRPL lending from the supplied confidential amendment's explicit overrides; do not add collateral, anonymous identities, first-loss guarantees, AI underwriting, or automatic settlement as requirements by default.
- Validate delegated integrations against the concrete SDK interfaces and a connected execution path. Optional method casts, guessed return shapes and disconnected UI smoke checks cannot establish that a financial flow works.
- Recover full-range confidential values from authenticated limb/history data and verify the resulting ciphertext. A whole-range discrete-log call is not a usable fallback for 63-bit balances or loan previews.
- Mock RPCs must enforce the real contract's argument shapes and pagination limits. A healthy server with failing dashboard reads is an integration bug to diagnose; require actual connected transactions before accepting a UI workflow.
- Keep a curve point's canonical hex representation distinct from a contract's JSON-encoded byte blob. Normalize at the UI/contract adapter boundary, and use actual Core wire encodings in integration fixtures; equal-looking hex strings are not interchangeable types.
- When adding social wallets, confirm the connector architecture from the latest user direction. Use NEAR Connect for Privy plus ecosystem wallets; do not replace it with a Privy-only account layer. Treat provider application credentials as deployment configuration, and distinguish configurable support from a verified live login.
